# 傳奇倖存者 v0.1 驗收標準

> **版本說明：** 本文件記錄《傳奇倖存者》**v0.1 早期原型**的規格／驗收歷史，包含當時不同的角色、武器、美術及波次機制，**不代表目前 v0.2 科幻機甲版本的玩法**。現行遊戲以 `spec/20261017_LegendarySurvivor_Scifi_v0.2.md` 與 SF-01～SF-17 的對應條款為準；原始歷史內容保留供版本追溯，AI 不得以本文件覆寫現行遊戲。

## 檔案職責

本檔案用於判定《傳奇倖存者》v0.1 是否達到“可開啟、可遊玩、可結算、可重開、可驗證”的合格線。

- 本檔案對應 `AGENTS.md` 開發流程裡的 step 1，由主 Agent 根據 spec 整理或確認。
- 本檔案只寫“什麼算透過”，不展開詳細測試步驟。
- 詳細測試用例和執行方法應由 `test-author` 根據本檔案輸出到 `docs/` 目錄。
- 覆蓋檢查應由 `acceptance-checker` 核對：每條驗收標準都要有真實測試或人工檢查證據。
- 玩法事實源是 `spec/遊戲機制.md`；視覺事實源是 `spec/視覺規格.md`；v0.1 範圍和素材邊界參考 `spec/v0.1-傳奇倖存者-歷史原型.md`、`assets/README.md` 及其子檔案。
- 如果本檔案和事實源衝突，以對應事實源為準，並先修正本檔案再繼續開發或驗收。

## 總透過口徑

v0.1 透過驗收，需要同時滿足下面幾件事：

- 遊戲能作為 Godot 4.x 工程直接執行。
- 一局能從開始進入戰鬥、升級、波次推進、勝利或失敗結算，並能重開。
- 核心玩法、UI、音效、反饋、效能和觀測證據都達到本檔案的標準。
- 每條驗收標準都有對應測試、截圖、幀序列、日誌、狀態快照或人工複核記錄。
- 不為了讓實現過關而降低驗收標準、測試要求或事實源口徑。

## 一、專案可執行與範圍

- **AC-RUN-01** 倉庫根目錄是 Godot 4.x 工程，包含 `project.godot`，主場景為 `scenes/Main.tscn`，主場景能直接啟動。
- **AC-RUN-02** 主場景啟動和正常遊玩時，沒有指令碼解析錯誤、資源載入錯誤或執行時致命錯誤。
- **AC-RUN-03** 執行時素材只引用 `assets/sprites/` 和 `assets/audio/sfx/` 中允許接入的資源，不把 `assets/source/` 當作執行時資源。
- **AC-RUN-04** 輸入、戰鬥、刷怪、升級、結算、音效和除錯觀測入口分模組實現，不能把主要規則混寫進 UI、動畫或一次性除錯指令碼裡。
- **AC-RUN-05** 波次、升級、貓、敵人、音效事件、數量上限等公共數值集中管理，有唯一口徑，不能散落硬編碼在多個指令碼裡。
- **AC-RUN-06** v0.1 不引入非目標內容：存檔、賬號、排行榜、商店、揹包、天賦樹、第二張地圖、隨機地圖、多人、後端、複雜 Boss、新增貓種、新增敵人技能、移動端適配或釋出打包最佳化。

## 二、可觀測與證據

- **AC-OBS-01** 遊戲支援固定隨機種子；同一個種子、同一組輸入和同一套除錯引數下，關鍵狀態推進可復現。
- **AC-OBS-02** 任意關鍵時刻能匯出狀態快照，至少包含：花子血量、最大血量、當前波次、波次進度、遊戲時間、遊戲狀態、場上敵人數、場上貓彈數、場上奶滴數、擊殺數、當前經驗、升級所需經驗、升級次數、已解鎖武器、各升級層數。
- **AC-OBS-03** 提供快速進入升級、勝利、失敗三個流程的除錯入口，不要求驗收者每次都完整打滿一局才能檢查這些狀態。
- **AC-OBS-04** UI、佈局、動態特效和結算頁必須有真實執行截圖或幀序列證據，不能只靠日誌、控制元件座標或 headless 結果判定透過。
- **AC-OBS-05** 每輪正式驗收至少保留戰鬥、升級彈窗、勝利或失敗結算三類截圖，以及一段能看到戰鬥動態的連續幀或短錄屏。

## 三、輸入、暫停與互動

- **AC-INPUT-01** 玩家能用 WASD 和方向鍵移動花子；上下左右和斜向移動都穩定，斜向移動不能明顯快於單軸移動。
- **AC-INPUT-02** 花子移動時鏡頭跟隨，玩家不能走出地圖視覺邊界或進入不可讀的地圖外區域。
- **AC-INPUT-03** 玩家不需要手動瞄準或主動攻擊；貓會從花子附近自動發射並攻擊敵人。
- **AC-INPUT-04** 升級三選一出現後，玩家能用滑鼠點選任意可選升級項；選中後升級立即生效並回到戰鬥。
- **AC-INPUT-05** 勝利和失敗結算頁都提供重開入口；點選重開後回到新一局初始狀態。
- **AC-INPUT-06** Esc 或 P 能暫停和恢復遊戲；暫停時戰鬥計時、刷怪、敵人、彈體和經驗移動停止，但暫停 UI 或恢復操作仍可用。
- **AC-INPUT-07** 升級彈窗期間戰鬥暫停，升級 UI 仍可點選；選定升級後戰鬥恢復。

## 四、核心迴圈

- **AC-LOOP-01** 一局從開始到結束形成完整閉環：進入地圖、自動放貓、刷怪、敵人掉經驗、升級三選一、波次推進、勝利或失敗、結算、重開。
- **AC-LOOP-02** 花子初始血量為 100；花子血量降到 0 時進入失敗結算。
- **AC-LOOP-03** 撐過第 5 波，或在規定時間記憶體活到最後，進入勝利結算。
- **AC-LOOP-04** 一局正常時長落在 3 到 5 分鐘內；除錯加速模式不受此限制，但不能改變正常模式口徑。
- **AC-LOOP-05** 結算頁展示：勝利或失敗、存活時間、擊敗敵人數、放出貓總數、最常用貓或最高傷害貓、升級次數。
- **AC-LOOP-06** 重開後，花子血量、波次、敵人、彈體、經驗、升級層數、已解鎖武器和計時都回到一局初始狀態。

## 五、戰鬥機制

- **AC-COMBAT-01** 花子與敵人發生身體接觸時，會按照 `spec/遊戲機制.md` 的受擊規則扣血，並觸發受擊反饋；受擊後進入短暫無敵，同一段無敵時間內重複接觸敵人不能連續扣血。不能出現正常畫面中牛已經接觸花子但血量不變的情況。
- **AC-COMBAT-02** 橘貓開局即擁有；橘貓發射後朝當時距離最近的敵人直線撲擊，不是隨機方向。
- **AC-COMBAT-03** 黑貓在第 1 波結束後自動解鎖；黑貓飛向敵人密集處，接近後觸發一次範圍爆炸並消失。
- **AC-COMBAT-04** 奶牛貓在第 3 波結束後自動解鎖；奶牛貓沿短弧線或迴旋彈道飛行，飛行途中可命中多個敵人，達到命中次數、飛出範圍或飛行時間結束後消失。
- **AC-COMBAT-05** 每隻貓彈都有明確的傷害、飛行速度、飛行時間、命中邏輯和同屏上限；達到上限後不能無限新增。
- **AC-COMBAT-06** 三種貓在機制上確實不同：橘貓按最近敵人直線撲擊，黑貓按敵群密集處觸發範圍爆炸，奶牛貓按短弧線或迴旋彈道掃場。
- **AC-COMBAT-07** 四種牛在機制上確實不同：普通牛直線追擊，小牛速度更快且更脆，厚皮牛血量更高且更慢，遠端牛保持距離並吐奶滴。
- **AC-COMBAT-08** 遠端牛的奶滴有明確傷害、飛行速度和發射間隔；奶滴數量和頻率不能密集到遮擋主要戰鬥。
- **AC-COMBAT-09** 敵人死亡後掉落經驗；經驗進入吸附範圍後自動飛向花子並增加升級進度。
- **AC-COMBAT-10** 螢幕外敵人只保留必要狀態；靠近花子一定距離後才進入完整追蹤、動畫和碰撞邏輯。

## 六、波次與成長

- **AC-GROWTH-01** 波次順序固定為：第 1 波普通牛，第 2 波加入瘋跑小牛，第 3 波加入厚皮大奶牛，第 4 波加入吐奶遠端牛，第 5 波混合牛群。
- **AC-GROWTH-02** 第 1 波結束後，已解鎖武器從「橘貓」變為「橘貓 + 黑貓」。
- **AC-GROWTH-03** 第 3 波結束後，已解鎖武器變為「橘貓 + 黑貓 + 奶牛貓」。
- **AC-GROWTH-04** 武器獲得不進入隨機升級池，只按波次固定解鎖。
- **AC-GROWTH-05** 升級使用三選一；每次出現 3 個升級項，均來自 U01 到 U04 的基礎屬性升級表。
- **AC-GROWTH-06** U01「貓貓連發」最多 4 層，作用於所有貓；每層效果為發射冷卻 -15%，具體疊加方式按事實源或已拍板配置的唯一口徑執行。
- **AC-GROWTH-07** U02「貓爪變鋒利」最多 4 層，作用於所有貓；每層效果為傷害 +20%，具體疊加方式按事實源或已拍板配置的唯一口徑執行。
- **AC-GROWTH-08** U03「貓群加速」最多 3 層，作用於所有貓；每層效果為飛行速度 +15%，具體疊加方式按事實源或已拍板配置的唯一口徑執行。
- **AC-GROWTH-09** U04「跑快一點」最多 3 層，作用於花子；每層效果為移動速度 +12%，具體疊加方式按事實源或已拍板配置的唯一口徑執行。
- **AC-GROWTH-10** 升級項達到上限後，不再出現在後續三選一里。
- **AC-GROWTH-11** 一局正常遊玩通常出現 4 到 6 次升級；用於驗收的固定種子應能證明這個節奏成立。
- **AC-GROWTH-12** U01、U02、U03 這類對“所有貓”生效的升級，必須覆蓋當時已解鎖的每一種貓，並從下一次發射起生效。
- **AC-GROWTH-13** 如果可選升級項不足 3 個，升級 UI 和選擇規則必須按事實源或已拍板配置處理，不能臨時塞入已達上限的升級項。

## 七、地圖、鏡頭與場景

- **AC-MAP-01** 遊戲使用一張固定戶外大地圖，不做地圖切換、隨機地圖、迷宮、鑰匙門或複雜探索。
- **AC-MAP-02** 地圖面積明顯大於螢幕，鏡頭只顯示地圖的一部分，而不是一次性顯示整張地圖。
- **AC-MAP-03** 設計解析度為 1920x1080；主地圖 `full_outdoor_map_painted_4096x2305.png` 一屏約看到整圖的四分之一，Camera2D zoom 保持在 0.8 到 1.2 之間。
- **AC-MAP-04** HUD 使用 CanvasLayer 或等價方式固定在螢幕上，鏡頭移動時 HUD 比例和位置不隨地圖漂移。
- **AC-MAP-05** 環境裝飾按 v0.1 畫面基準疊加，只增加畫面層次，不承擔複雜探索或關鍵玩法邏輯；玩家出生點和刷怪區附近保持可讀、不過度擁擠。
- **AC-MAP-06** 地圖邊界透過圍欄、樹牆、石牆、水面或其他視覺方式表達清楚，玩家不會因為邊界不清而誤判可走區域。

## 八、UI 與畫面

- **AC-UI-01** HUD 佈局符合 `spec/視覺規格.md` 和 v0.1 戰鬥 HUD 畫面基準：左上頭像、血條、經驗條、已解鎖貓圖示、頂部波次提示、右上擊殺數和計時的相對位置、比例、層級和對齊關係不能明顯偏離。
- **AC-UI-02** 升級三選一面板居中彈出；彈出時戰場壓暗，三個升級項以三張並排的豎向大卡片呈現。每張卡片都能清楚看到升級名稱、效果、當前層數或上限資訊，並且點選反饋清楚。
- **AC-UI-03** 勝利和失敗結算面板居中彈出，按鈕和結算統計不互相遮擋。
- **AC-UI-04** 血條、經驗條、圖示、按鈕、標題、統計文字之間不重疊、不裁切、不被戰鬥特效遮住；關鍵遮擋數為 0。血條和經驗條的槽體、內容區和填充區對齊，按 `spec/視覺規格.md` 中的 HUD 畫素容差規則驗收；填充不能偏出邊框、懸空、錯位或出現孤立色塊。
- **AC-UI-05** UI 文案使用中文；畫面上不出現“已完成某需求”之類給驗收者看的說明文字。
- **AC-UI-06** 角色、貓彈、奶滴和四種牛的方向動畫符合 `spec/視覺規格.md`：執行時必須按當前移動或飛行方向切換對應 8 向動畫，不能只載入 8 向圖集但固定播放單一方向。
- **AC-UI-07** UI 控制元件、命中、爆炸、經驗和死亡等 VFX 使用按執行尺寸準備的定製資產或粒子效果；資產位置必須符合 AC-RUN-03，不能直接切原始參考大圖湊成最終效果，也不能只用純色框或預設控制元件代替。定製資產不能作為改變 Spec 繫結結構的理由；如果 Spec 已指定視覺結構，最終實現必須先滿足結構一致，再判斷風格完成度。
- **AC-UI-08** 畫面整體保持手繪描邊、暗色高對比的漫畫街機風；不做畫素化處理，匯入過濾按 `assets/sprites/README.md` 的當前規則執行。不把參考圖當成最終 UI 直接貼上去，但必須保留 Spec 明確標為視覺目標的結構、比例和視覺重心。
- **AC-UI-09** 升級彈窗必須以 `spec/v0.1-畫面基準-升級彈窗示意.png` 作為視覺目標。正式驗收時必須儲存真實執行截圖，並與示意圖並排核對：彈窗位置、戰場壓暗、三卡並排結構、卡片豎向比例、卡片間距、外框和內框層級、下半部說明區、底部圓形徽章或圖示位都不得明顯偏離。改成長條按鈕列表、普通選單列表、預設系統面板，或只保留“居中三選一”但結構不像示意圖的方案，視為不透過。
- **AC-UI-10** 升級卡、HUD 主框、結算面板、暫停面板和提示橫幅這類核心 UI，必須使用 `assets/sprites/ui/runtime/` 中的執行時 UI 資產，或使用由這些資產建出的 `.tres`；不能主要依賴 `draw_rect`、`draw_line`、`draw_circle`、預設控制元件或單色 `StyleBoxFlat` 模擬。升級卡必須能追溯到 `assets/sprites/ui/reference_crops/` 中的對應參考 crop，並保留參考 crop、執行時資產、真實執行截圖 crop 和並排對照證據。
- **AC-UI-11** 正常遊玩截圖和正式視覺驗收截圖中不得出現除錯輔助痕跡：碰撞半徑圈、攻擊半徑圈、啟用範圍圈、刷怪區矩形、地圖邊界矩形、敵人型別文字標籤、AI 狀態標籤、物件池標記、座標標記或開發者輔助線。需要這些資訊時必須透過顯式除錯入口單獨截圖，並在報告裡標明除錯輔助層已開啟。

## 九、反饋與音效

- **AC-FEEDBACK-01** 敵人被打到時有閃白、閃爍、粒子或其他可見受擊反饋。
- **AC-FEEDBACK-02** 貓命中有反饋；黑貓爆炸有範圍特效；奶牛貓掃場能看出命中過程。
- **AC-FEEDBACK-03** 花子受擊時有可見反饋，並能從 HUD 血量變化看出扣血。
- **AC-FEEDBACK-04** 戰鬥中有輕微震屏、視覺抖動或短暫停頓等打擊反饋，但不能影響玩家讀 UI 和走位。
- **AC-FEEDBACK-05** 下列事件都有對應音效真實觸發：發橘貓、發黑貓、發奶牛貓、奶滴、命中、黑貓爆炸、敵人死亡、花子受擊、吃經驗、升級、選擇升級、波次開始、解鎖新貓、勝利、失敗。
- **AC-FEEDBACK-06** 配置中的音效事件都能載入到真實音訊檔案；不能出現事件指向缺失檔案、空音訊或靜音佔位的情況。

## 十、效能與穩定性

- **AC-PERF-01** 貓彈、奶滴和敵人都有同屏或活躍數量上限；達到上限後節點數量不能無限增長。
- **AC-PERF-02** 貓彈、敵人和常見掉落物使用物件池或等價複用方式，避免大量反覆建立和銷燬造成卡頓。
- **AC-PERF-03** 第 5 波混合牛群壓力場景下，遊戲不能卡死、長時間凍結或出現連續致命報錯。
- **AC-PERF-04** 一局從開始連續跑到勝利或失敗，過程中不能出現記憶體、節點數量或日誌錯誤持續增長到不可控的情況。
- **AC-PERF-05** 除錯加速、截圖、幀序列和狀態快照只能作為輔助驗證工具，不能改變正常模式下的玩法結果。

## 十一、整體成型

- **AC-SHAPE-01** 不看檔案的驗收者看 10 秒正常戰鬥畫面，能說出“花子在自動放貓打奶牛”或意思等價的描述。
- **AC-SHAPE-02** 不看檔案的驗收者看正常戰鬥片段後，能用自己的話說出三種貓的大致差異；這裡驗體感可讀性，不替代 AC-COMBAT-06 的機制檢查。
- **AC-SHAPE-03** 不看檔案的驗收者看正常戰鬥片段後，能用自己的話說出四種牛的大致壓力差異；這裡驗體感可讀性，不替代 AC-COMBAT-07 的機制檢查。
- **AC-SHAPE-04** 選擇不同升級後，戰鬥效果有可感知變化：貓更多、貓更痛、貓更快，或花子更靈活。
- **AC-SHAPE-05** 結算頁能證明這是一局完整遊戲，而不是隻展示一個勝利或失敗文字。
- **AC-SHAPE-06** 不看檔案的驗收者看正常戰鬥畫面時，應認為主要可見元素屬於遊戲世界、角色、UI 或戰鬥特效，而不是開發除錯標記。

## 十二、需要拍板的數值口徑

下面這些不是測試用例，也不是本檔案偷偷替 spec 定數值。它們是 `test-author` 寫詳細測試前必須有唯一口徑的專案。口徑可以來自 `spec/遊戲機制.md` 的後續補充，也可以來自使用者確認後的集中配置；但不能由寫實現或寫測試的 Agent 臨時猜一個。

- 花子受擊後的無敵時長。
- 同屏貓彈、奶滴和敵人的上限。
- 三種貓的基礎傷害、飛行速度、飛行時間、發射冷卻和各自上限。
- U01 到 U04 的升級疊加方式：每層按加法疊加還是乘法疊加，以及 UI、戰鬥計算和狀態快照如何統一展示。
- 當可選升級項不足 3 個時，三選一介面如何處理。
- 黑貓爆炸半徑和爆炸傷害。
- 奶牛貓可命中次數、飛行範圍和飛行時間。
- 四種牛的血量、速度、接觸傷害、經驗掉落和活躍範圍。
- 遠端牛奶滴的傷害、速度、發射間隔和最大數量。
- 經驗吸附範圍和升級所需經驗曲線。
- 五波的正式時間節奏、刷怪間隔和敵人組成權重。

這些數值一旦拍板，應集中寫入事實源或配置，並由測試用例按同一口徑驗證。
