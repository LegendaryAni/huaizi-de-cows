# v0.1 一局制可用版：傳奇倖存者

> **版本說明：** 本文件記錄《傳奇倖存者》**v0.1 早期原型**的規格／驗收歷史，包含當時不同的角色、武器、美術及波次機制，**不代表目前 v0.2 科幻機甲版本的玩法**。現行遊戲以 `spec/20261017_LegendarySurvivor_Scifi_v0.2.md` 與 SF-01～SF-17 的對應條款為準；原始歷史內容保留供版本追溯，AI 不得以本文件覆寫現行遊戲。

v0.1 的目標：在倉庫根目錄完成一個 Godot 4.x 專案（含 `project.godot`），交付《傳奇倖存者》的一局制核心閉環：可開啟、可遊玩、可結算、可重開、可驗證。桌面執行優先，保留 Web 匯出可能。

## 必須交付的閉環

按 `spec/遊戲機制.md` 完整實現一局制核心閉環：

1. 進入固定大地圖。
2. 花子可以移動，鏡頭跟隨。
3. 花子自動放貓攻擊敵人。
4. 敵人按波次出現並形成壓力。
5. 敵人死亡後掉經驗，經驗吸附到花子並推進升級。
6. 升級時出現三選一，玩家選擇後回到戰鬥。
7. 指定波次結束時固定解鎖新貓。
8. 花子血量歸零進入失敗結算。
9. 撐過最後一波進入勝利結算。
10. 結算頁能重開新一局。

## 必須滿足的視覺入口

按 `spec/視覺規格.md` 完整實現 v0.1 所需視覺表現：

- 正常遊玩入口呈現正式畫面，不混入除錯輔助層。
- 角色、貓彈、奶滴和牛按當前方向使用對應方向動畫。
- HUD、升級彈窗、結算面板、VFX 和正式截圖限制符合視覺規格。
- `spec/v0.1-畫面基準-戰鬥HUD示意.png` 約束戰鬥 HUD 的資訊位置、比例、層級和對齊關係。
- `spec/v0.1-畫面基準-升級彈窗示意.png` 約束升級彈窗的結構、比例和視覺重心。

## 素材邊界

- 執行時素材只用 `assets/sprites/`（含 `.spriteframes.tres`）和 `assets/audio/sfx/` 中允許接入的資源。
- `assets/source/` 是源圖目錄，不接入執行時。
- `ui_assets_painted.png`、`combat_assets_painted.png` 等 painted 圖只作風格參考；最終執行時 UI 和 VFX 使用按實際尺寸準備的執行時資產。
- `assets/sprites/ui/reference_crops/` 是控制元件級視覺參考；`assets/sprites/ui/runtime/` 是 Godot 實現應引用的執行時 UI 資產目錄。
- Godot 程式碼不引用 `.import` 檔案；`.import` 只作為 Godot 匯入後設資料存在。
- 音效是必交項：接入 `assets/audio/sfx/` 的真實音訊，戰鬥、UI、升級、波次、勝負等關鍵事件觸發對應 SFX。
- 不移動、不改名現有素材目錄。

## 程式碼結構

輸入、戰鬥、刷怪、升級、結算、音效、觀測入口分模組實現。公共數值集中管理，不把規則和數值寫死在 UI、動畫或特效指令碼裡。

## 可除錯與可驗證

- 主場景可直接執行，主控臺無指令碼報錯和資源載入錯誤。
- 關鍵狀態可觀測：玩家血量、當前波次、敵人數量、貓彈數量、奶滴數量、擊殺數、經驗、升級次數、已解鎖武器和遊戲狀態。
- 支援固定隨機種子。
- 提供能快速驗證升級、勝利、失敗和關鍵戰鬥狀態的除錯入口。
- 允許提供除錯輔助層，但必須預設關閉，只能透過明確引數或驗證入口開啟；除錯截圖和報告必須標明除錯輔助層已開啟。
- UI、佈局和動態特效必須用真實執行截圖或動態幀序列驗證，不能只靠 headless smoke、控制元件 rect 或日誌指標判斷。
- 頁面和 UI 上不寫“已完成某某需求”之類說明文字，完成與否靠遊戲本身和驗證證據體現。
