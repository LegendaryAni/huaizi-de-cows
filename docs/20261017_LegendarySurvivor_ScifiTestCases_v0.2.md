# 《傳奇倖存者》科幻改造測試案例 v0.2

日期：2026-10-17。角色：獨立 test-author。狀態：**測試設計完成，尚未執行**。

事實源：`spec/20261017_LegendarySurvivor_Scifi_v0.2.md`；合格線：`docs/development/acceptance-standard.md` 的 SF-01～SF-17。本文不修改合格線，不將夾具、加速測試或自動操作當作真人試玩。

## 1. 執行入口與證據契約

- 正式入口是 `project.godot` 的主場景，必須另以一般視窗啟動並操作；專用測試場景成功不代表正式入口成功。
- 預定觀測入口為 `scripts/scifi/ScifiMain.gd`：`snapshot()`、`start_run(loadout)`、`choose_card(id)`、`use_skill(slot)`、`finish_run(won)`。本節為測試需要的介面契約，實作尚待核對。
- 預定 CLI：`godot --path <repo> -- --scifi-test=<scenario> --scifi-report=<absolute-report.json> --scifi-save=<isolated-directory> --seed=N`。一般互動證據不能使用 `--headless`。Godot 可執行檔的實際路徑由執行者記錄。
- `start_run` 與 UI 共用配裝驗證；loadout 含一個 weapon key 與兩個不同的 skill key。`choose_card` 僅接受目前可見候選 ID；無效／過期 ID 不改狀態。slot 固定 0/1，對應 Space/E。
- `finish_run` 只供 `settlement` 等明確標示夾具測試；正常成長不得呼叫它、改 HP、生成額外 XP／金錢、縮短時間或修改敵方狀態。
- 另需測試入口：固定場上敵人／武器／改裝／XP／時間的夾具、儲存失敗注入、購買與重試結算入口、正常 Input action 驅動。均由明確 `--scifi-test` 開啟；預設正常流程不啟用夾具或除錯圖層。
- `snapshot` 至少記錄：版本、seed、run_id、遊戲狀態、戰鬥時間／階段、HP／maxHP／位置／速度／朝向、武器等級／進化／實際傷害／CD、改裝層數、目前卡片與排隊升級、技能 key／剩餘 CD／持續時間／護盾／無敵、敵人型別／位置／HP／控制狀態、敵彈清單（位置／速度／傷害）、合法移動邊界 `movement_bounds`、Boss 生成次數與攻擊狀態、活躍及已配置池數量、擊殺／XP／本局信用點／里程碑、永久升級／錢包／待結算 ID／已結算 ID、儲存狀態／錯誤。
- 測試診斷需提供具 timestamp、entity_id、source_id 的 attack/hit/death/credit/audio/pool/save 事件與目前載入資源路徑；自動策略可讀實體位置，但不得改實體。診斷不能在正式畫面常駐顯示。
- 數值斷言對照集中 Config 與當時已批准 spec，數值更動時保留配置版本／差異。時間容差最多一個 physics tick，浮點運算容差 0.01；不得用容差放寬需求。
- 每個 scenario 輸出：逐項斷言、輸入、開始／結束快照、事件、引擎版本、配置版本、存檔隔離路徑、exit code 及錯誤。缺證據標 `not_verified`，不能只寫 PASS。
- 報告及截圖存入本輪獨立 evidence 目錄，不能覆寫舊結果。正式畫面與 `debug`／fixture 畫面分名；截圖保留原尺寸，連續片段保留時間資訊。

## 2. 可執行測試案例

### T01 正式啟動及架構（SF-01）

1. 檢查 project main_scene、GDScript 依賴及 runtime 資源引用；執行 Godot import／parse。
2. 不帶測試引數從主場景啟動，配裝出擊，走動／升級／暫停／返回；儲存啟動與戰鬥日誌。
3. 斷言正式主場景確實載入新版，無解析、載入、致命執行錯誤；輸入、戰鬥、成長與結算實際由 Godot 執行，外部程式僅操控／觀測。

### T02 素材、八方向及資產隔離（SF-02、SF-13）

入口 `assets-directions`，加正式入口手動走位。

1. 核對來源／複製清單和 ID：1103、2101、2106、2103、2105、3101；驗證來源雜湊或可追溯轉換紀錄。檢查正式載入路徑均為本專案 runtime 資產，無來源絕對路徑依賴。
2. 主角與四怪分別沿 e/se/s/sw/w/nw/n/ne 移動，錄至少各兩個完整動畫週期；切待機再移動。將原來源各方向與實際影象並列，核對對映 2/1/0/7/6/5/4/3，不能只測 animation 名稱。
3. 量測每角色腳底錨點、顯示倍率及跨幀 bounding box；靜止／移動無縮放跳動或腳底飄移。保留逐向 contact sheet、幀時長及匯入 Nearest 證據。Boss 檢查實際具備的正式動作與資產，不要求不存在的八向素材。

### T03 地圖、移動與鏡頭（SF-03）

入口 `movement`，正式 UI 鍵盤操作。

1. 核對地圖 4096×2305、設計視口 1920×1080、zoom=1。分別用 WASD 與方向鍵每方向走 2 秒，排除接觸／技能；對照位移與 Config 速度，斜向距離與單軸相同。
2. 走至四邊及四角，使用衝刺朝外；碰撞位置不越合法邊界。鏡頭跟隨且 HUD 固定；擷取中心、邊角與出生區，實際可走範圍與工業設施邊界一致。
3. 在正常畫面目視出生與刷怪周邊可讀，無不明地圖外空洞。快照與幀序列共同驗證，不能只查常數。

### T04 配裝與最近選擇（SF-04、SF-11）

入口 `loadout`，另逐項點選正式配裝。

1. 遍歷六武器×六種技能配對，共 36 組，確認所有選項初始開放、有效組合能進場且 HUD／快照一致。
2. 以未知武器、未知技能、少一技能、三技能、相同技能兩次、空配裝呼叫正式驗證入口；均拒絕，不開局、不扣資源、不破壞最近有效配裝。
3. 儲存合法組合、關閉重啟讀回；按 Space/E 與 HUD 所示 slot 一致。儲存失敗時顯示錯誤且不假稱已儲存，詳 T11。

### T05 六武器、命中與記帳（SF-05、SF-14）

入口 `weapons`。每武器逐一測一／二／三／四／五級、永久層數 0／5；每格均需實際自動發射、命中HP差及相鄰發射間隔對Config的斷言，不能只查計算函式或一級／五級端點。

| key | 測試佈置與真實斷言 |
| --- | --- |
| rail | 距離不同的敵人與空場；自動朝最近目標直線射擊，命中 HP 差及發射間隔符合配置，無目標不憑空記命中。 |
| grenade | 一個近端孤立敵與遠端密叢集；瞄準密叢集，爆炸僅命中半徑內物件，距離邊界內／外均測。 |
| blade | 弧線不同位置放多敵；追蹤飛行軌跡證明曲線／迴旋、多個真實命中，單次可重命中的規則與集中設定一致。 |
| arc | 連鎖範圍內外分佈多敵；事件鏈與 HP 差證明逐目標連鎖，範圍外不誤中，不把單目標傷害倍增當連鎖。 |
| thermal | 近敵、側後敵、射程外敵；朝近敵錐形噴流，僅有效角度／距離命中，持續傷害間隔和 duration 符合配置。 |
| frost | 射線上與偏離目標；真實命中且移速下降，強度與時長符合配置，結束恢復，不以畫線代替傷害。 |

另讓兩種傷害同幀擊殺相同 entity_id，以及集束／連鎖重疊命中死亡物件；每敵僅一筆 death、一筆擊殺、一次 XP 與信用點。將第三武器填滿後，任何公開取得入口都不能增成四把；每把最多五級。保留傷害／CD 原始事件和視覺片段。

### T06 六改裝與進化（SF-06、SF-14）

入口 `evolutions`，遍歷 rail/firecontrol、grenade/blast、blade/propulsion、arc/capacitor、thermal/heat、frost/cooling。

1. 各測武器4＋改裝3、武器5＋改裝2，候選不得含進化；武器5＋改裝3時成為合法候選，但未選中前行為不得提前改變。
2. 選中進化後仍佔原欄、武器等級保持5、進化旗標一次，後續候選不再提供同進化。六改裝均在0～3層對照實際效果，滿層不得再增加。
3. 以同配置、同敵人佈置作前後對照：rail 穿多敵；grenade 爆炸散子彈並能命中；blade 同次雙刃；arc 真實連鎖增加；thermal 射程變長並穿透；frost 光束變寬且緩速更強、最終不超65%。需 HP／位置／事件與影片共同證明；傷害額外倍率亦依配置核對。

### T07 選牌、封頂與戰鬥凍結（SF-07）

入口 `cards`。

1. 從正常擊殺拾取 XP 開啟升級，以滑鼠分別點三個位置；新武器／強化／改裝／進化的文字、層數及立即結果一致。
2. 遍歷一／二／三把武器和各項封頂組合；比較完整合法候選集，顯示卡不得重複、非法或已滿級，滿槽排除新武器。用只剩2、只剩1項的夾具核對實際卡數及點選區。
3. 三武器5級並進化、六改裝3層；候選只提供合法修復／信用點補給，選擇後有真實效果，HP 不溢位、金錢不重記。
4. 出卡前發射彈體、置敵及 XP 在移動中，使用兩技能；停留選單5秒，時間、刷怪計時、位置、HP、CD／持續時間完全不變。UI 可選，選後恢復。累積多次升級時每次選牌最多續開一個，不同幀無聲跳過，不因卡片重送 ID 雙加層。

### T08 四技能與六配對（SF-08、SF-12）

入口 `skills`。六配對完整測：dash/pulse、dash/shield、dash/repair、pulse/shield、pulse/repair、shield/repair；slot 次序反轉至少再各測一次，以排除鍵位繫結錯誤。

1. 每組透過正式 start_run 開局，兩招 CD=0；Space/E 分別可用，施放 slot0 不重置 slot1。CD 中重按不觸發，CD 到0才可再用；永久技能CD層0／5符合配置。
2. dash：量測240px／0.18s；途中接觸敵人或敵彈不扣HP，結束後恢復正常受擊，四邊四角不越界。
3. pulse：範圍內普通敵停1.5s；特別將砲座置於即將發射時刻，癱瘓期間不移動、不發射，結束後正常恢復。範圍外砲座繼續行動。Boss 同時位於範圍內，僅移速降30%而仍能移動／攻擊，效果結束恢復，不可硬控或持續鎖死。
4. shield：吸收最大HP35%，維持4s；先以低於盾值傷害、再大於剩餘盾值傷害驗證吸收與HP餘傷；不多層疊加，時間到即消失。
5. repair：受傷／接近滿血／滿血分別施放，只回最大HP25%且不超max；不憑空增加最大HP。
6. 技能有剩餘CD與持續時間時分別用 Esc、P 暫停5秒及開啟升級5秒；全部凍結，恢復後繼續原剩餘值。正常暫停中不能施放技能。

### T09 敵人、階段與首領勝負（SF-09）

入口 `stages-boss` 的邊界夾具，加完整正常一局。

1. 每種敵人分別測追擊向量、速度／HP、遠端400px距離調整、2.4s發射間隔及敵彈傷害／速度／壽命；四者的差異須在行為及畫面皆可識別。
2. 於119.9/120、239.9/240、359.9/360、479.9/480秒附近記快照與生成事件；敵種不早於對應階段，後段有混編，刷怪間隔符合配置。
3. 480秒生成 Boss 一次；持續跨600秒、暫停／恢復及升級後都不再生成、不自行勝利。Boss 衝撞與扇形彈先有可見前搖再命中，儲存連續片段。
4. 正常傷害擊殺 Boss 即勝利；普通敵仍存活不阻擋。HP到0即失敗；結束後不繼續計時／傷害／發獎；下一局 Boss 計數重置。同一模擬步玩家HP歸零及Boss死亡時必須失敗優先，僅一筆失敗結算，不可先加通關獎。

### T10 收益與永久交易（SF-10）

入口 `economy`，使用隔離成長檔及清楚標示夾具。

1. 以已知 K 次擊殺與時間 T 結算，預期收益 K＋15×floor(T/60)＋(勝利200，否則0)；在59.9/60/120附近、暫停、重複快照驗證每個里程碑只給一次。
2. 勝敗各一場檢查本局收益全入錢包；重複結算／重開不得再發。
3. 四項依次購買1～5級，逐級價格60/100/160/240/340；HP／傷害／兩CD的加法倍率依spec核對。購買後重啟開始新局仍有效。
4. 差1點、恰好價格、超額三種餘額；滿級、未知key、儲存失敗均不能扣錢或加層。成功交易在儲存完成後才套用，重啟值與當前一致。

### T11 原子儲存、損壞、冪等與重試（SF-11）

入口 `save-faults`。只在獨立測試目錄注入故障，先記檔案 hash；不得改正式 user dir。

1. 首存、二次儲存，檢查版本、信用點、永久層數、配裝、run/settlement ID及備份；原有huazi_scores.json不變。模擬暫存寫入失敗、flush／替換前中斷、替換失敗，重啟只能讀到完整舊版或完整新版，不能半檔。
2. 破壞主檔、保留有效備份；另測主檔與備份皆壞、未來version、錯誤型別。顯示問題、保留原檔hash；不得靜默重設並覆寫。可恢復時使用已驗證備份，不汙染格式不相容原檔。
3. 結算先寫含run_id及完整收益的pending journal。journal成功、主成長檔提交失敗時，UI顯示待儲存、收益及重試；重啟仍可讀journal重試。重試成功一次，再重試／重送相同ID／重啟後重送，錢包只增加一次。另測全部寫入失敗：記憶體保留完整待結算且阻止靜默離開，明示無法儲存；此情況不承諾抵抗強殺或磁碟損壞。
4. 結算成功寫檔但回應前故障，重啟以已結算ID阻止重發；購買同樣測寫入失敗不扣款、不加層。失敗待結算時離開／重開不得靜默遺失，需可見處置或阻擋；關窗測試儲存失敗提示。
5. 報告保留每次故障位置、前後hash、待結算與落盤狀態，不以「函式回true」代替讀回驗證。

### T12 既有成績與完整 UI 閉環（SF-12）

入口 `flow-compat`，正式視窗滑鼠鍵盤操作。

1. 檢查名稱及現有custom user dir未改。將合法舊成績fixture複製到隔離user dir，從正式歷史成績入口讀取，原內容與排序資訊保留；每次流程後比較舊檔不得被清空。
2. 配裝→戰鬥→拾取／升級→暫停／恢復→勝利／敗北→收益→購買→重啟→新出擊，各儲存快照與可點選畫面。
3. 進行中要求離開／重開／關窗，顯示未結算收益會放棄；取消保持原局，確認返回配裝，敵人、彈體、XP、HP、武器、改裝、時間、技能CD回新局初值，永久值保留。儲存失敗的結算不得走一般放棄路徑靜默丟棄。

### T13 UI、風格與正式資產（SF-13）

入口 `visual-capture`，此測試需要真實有畫面的 Godot 執行，交獨立 visual-reviewer。

1. 儲存畫素結構基準與來源crop、runtime資產、實際UI crop並列；畫面涵蓋配裝、通常戰鬥、技能CD、Boss血條、三張升級卡、兩張／一張候選、暫停、勝敗、永久升級、儲存失敗。
2. 在1920×1080及實際Windows預設視窗檢查：主角頭像／HP／XP／武器左上、階段上中、擊殺／時間右上；條槽／填充對齊；升級置中三張並排竪向大卡、壓暗戰場。所有按鈕實際可點。
3. 深色工業、鋼灰／暖金／青／橘紅與畫素Nearest一致，中文清楚，核心UI使用正式runtime影象；不以純色預設面板、幾何圈或字標替代。關鍵遮擋／裁切及正常除錯痕跡均為0；只有日誌／控制元件座標不算透過。

### T14 真實回饋與音效（SF-14）

入口 `feedback-audio`，有畫面且啟用音訊。

1. 逐事件觸發六武器發射／命中、爆炸、進化、敵死、受擊、拾取、四技能、升級、選牌、階段、勝利／失敗；事件timestamp與畫面／音訊對齊，不接受只有資源存在。
2. 解碼每個實際音檔，檢查非空、有非零樣本；核對播放事件、音量、bus、BGM迴圈及結算切換，實際聆聽錄音確認可聞、不破音。
3. 粒子／動畫能識別命中、範圍、玩家受傷與技能結果；短暫震屏不造成UI漂移或遮擋。正常錄影不得開除錯幾何標記。

### T15 上限、復用、重現與長跑（SF-15）

入口 `pool-stress`、`replay` 加正常完整局。

### T16 固定正常成長策略（SF-16）

入口 `growth`。以下策略在遊戲實作前固定，後續校準不可修改策略、種子、門檻或偷偷重跑挑最好結果。

**存檔與時間**：seed 17／41／73各一個全新隔離目錄，信用點與永久層數均0。每條最多5場，每場使用同一條base seed；run_id仍須唯一。`Engine.time_scale=1`、標準physics tick，記錄真實開始／結束時刻及累積戰鬥時間。升級／交易UI時間單列，不將其當戰鬥時間。不呼叫fixture、finish_run，不注資、無敵或修改敵人／Boss。

**配裝**：每場 rail＋dash/repair，slot0=dash、slot1=repair。自動武器使用原生瞄準，外部程式只發正式移動／技能Input與公開UI／交易入口。可讀snapshot的敵人、彈體及邊界位置，這是全資訊自動操作，必須明確揭露，結果不代表真人。

**移動**：每0.10秒重算八個單位方向；以玩家位置加方向×速度×0.5秒作預測點，超出合法邊界的方向剔除。為每方向算預測點與所有存活敵／敵彈的最小距離，取最大者；同分選預測點最接近地圖中心者，再同分依 e/se/s/sw/w/nw/n/ne固定順序。兩次重算之間保持Input方向；沒有合法方向則停止。位置資料空時走向中心。不得傳送或直接設定玩家position。

**技能**：每0.10秒在HP≤最大HP75%且repair CD=0時按E；最近敵／敵彈距離≤100px且dash CD=0時按Space，沿目前合法移動方向；兩者同時符合時先repair再dash。技能失敗不改CD，不用隱藏能力。

**選牌**：每次合法候選依下列固定排序取第一張：rail進化→rail升級→firecontrol→新arc→arc進化→arc升級→capacitor→新grenade→grenade進化→grenade升級→blast→其他改裝依 heat/cooling/propulsion→其他新武器依 thermal/frost/blade→其他武器升級／進化依key字典序→修復→信用點。不可見選項不跳過UI直接獲得。相同型別再以card id字典序消歧。選牌延遲固定0.5真實秒。

**購買**：每場正常勝敗且收益儲存成功後，迴圈hp→damage→weapon_cd→skill_cd，每次購買一級；下一指定項不足資源即停止購買，指標留到下場；滿級項跳過。僅花當條線實際賺得資源。五場內一旦首次通關，記錄場數後該條可停止；未勝則開始下一場，不跳過敗局。

**斷言與證據**：三條均第五場內通關，三條首次通關場數中位數3～5；每場合法Input、選牌、購買、收益、前後存檔、配置hash、seed、狀態、首領死亡事件、退出原因全部落盤。1／2場早勝照實記，不強迫敗局。若中位數小於3或任一超5即本項失敗，回報配置校準需求；真人難度／樂趣仍為待試玩。只允許以保持策略的後續配置版本重跑整個三seed矩陣，保留所有失敗基準與差異。
