# 傳奇倖存者 v0.1 詳細測試用例

> **歷史版本範圍：** 此文件記錄《傳奇倖存者》v0.1 早期花子／貓牛原型，非現行科幻機甲版玩法。最新 v0.2 原始碼與規格請見 [開發分支](https://github.com/LegendaryAni/legendary-survivor/tree/feature/cinematic-menu-v3)。


## 文件職責

本文件把 `docs/development/acceptance-standard.md` 中的 v0.1 驗收標準轉成可執行、可觀察、可複核的測試用例。

本文件只寫測試設計和證據要求，不寫產品實現，不改驗收標準，不替 `spec/遊戲機制.md`、`spec/視覺規格.md` 或素材文件另立口徑。

## 依據

- 驗收標準：`docs/development/acceptance-standard.md`
- v0.1 範圍：`spec/v0.1-傳奇倖存者-歷史原型.md`
- 玩法和數值事實源：`spec/遊戲機制.md`
- 視覺事實源：`spec/視覺規格.md`
- 素材邊界：`assets/README.md`、`assets/sprites/README.md`

## 測試入口規劃

當前用例按下面幾類入口設計。這裡是測試要求，不假定這些腳本或參數已經存在；主 Agent 後續應按本文件補齊對應驗證入口。

| 入口 | 用途 | 需要補齊的能力 |
| --- | --- | --- |
| Godot headless smoke | 驗證工程可打開、主場景可加載、執行時無致命報錯 | 能在無窗口模式啟動專案、加載 `scenes/Main.tscn`、執行指定秒數、輸出日誌 |
| 固定隨機種子執行 | 驗證同種子同輸入可復現 | 支持傳入 seed、除錯參數、輸入腳本或錄製輸入，並導出狀態快照 |
| 狀態快照導出 | 驗證玩法數值、波次、對象數量、升級層數、勝負狀態 | 任意關鍵時刻導出 JSON 或等價結構化文件 |
| 除錯快速流程 | 快速進入升級、勝利、失敗和指定波次 | 支持 `upgrade`、`victory`、`failure`、`wave`、`combat_pressure` 等場景參數，不改變正常模式口徑 |
| 真實窗口截圖和幀序列 | 驗證 HUD、升級彈窗、結算頁、方向動畫、VFX 和除錯輔助層限制 | 能保存 1920x1080 真實執行截圖、連續幀或短錄屏，並保留文件名和場景說明 |
| 人工視覺複核 | 驗證體感可讀性、畫面基準對照和整體成型 | 至少 1 名未參與實現的複核者，按本文件記錄觀察結論 |

## 證據目錄建議

每輪正式驗收建議把證據放在 `reports/v0.1-acceptance/<YYYYMMDD-HHMM>/`。如果主 Agent 後續指定別的報告目錄，以主 Agent 指定為準。

證據至少包括：

- `logs/`：headless、窗口執行、報錯掃描日誌。
- `snapshots/`：狀態快照 JSON。
- `screenshots/`：正常戰鬥、升級彈窗、勝利或失敗結算、必要的除錯輔助層截圖。
- `frames/` 或 `videos/`：連續幀或短錄屏。
- `visual-review.md`：人工視覺複核記錄。
- `coverage.md`：本輪執行的用例、覆蓋 AC、通過和失敗項。

正式截圖文件名必須能區分正常畫面和除錯輔助層，例如：

- `combat_hud_normal.png`
- `upgrade_modal_normal.png`
- `result_victory_normal.png`
- `combat_debug_ranges_enabled.png`

## 通用前置條件

除非單個用例另有說明，預設前置條件如下：

- 使用儲存庫根目錄 `/Users/aya/dev/harness-dev-demo`。
- 使用 Godot 4.x 執行專案。
- 正常模式不啟用除錯輔助層。
- 設計視口按 1920x1080 驗證視覺佈局。
- 玩法數值按 `spec/遊戲機制.md` 的 v0.1 數值口徑驗證。
- 執行時素材邊界按 `assets/README.md` 和 `assets/sprites/README.md` 驗證。

## TC-RUN-01 工程啟動與主場景加載

目的：確認專案本身能作為 Godot 4.x 工程打開，主場景能直接啟動。

覆蓋 AC：AC-RUN-01、AC-RUN-02

前置條件：

- 儲存庫根目錄存在。
- Godot 4.x 命令行可用。

操作步驟：

1. 在儲存庫根目錄執行 headless smoke，加載專案並啟動主場景。
2. 記錄 Godot 版本、專案路徑、主場景路徑。
3. 執行至少 10 秒遊戲時間後退出。
4. 掃描控制檯日誌和 Godot 日誌。

通過標準：

- 根目錄包含 `project.godot`。
- 專案主場景為 `scenes/Main.tscn`。
- 主場景能啟動並進入可執行狀態。
- 日誌中沒有腳本解析錯誤、資源加載錯誤或執行時致命錯誤。

證據產物：

- headless 執行日誌。
- Godot 版本記錄。
- 主場景路徑記錄。

## TC-RUN-02 執行時素材引用邊界

目的：確認執行時沒有把源素材目錄或禁止路徑接入遊戲。

覆蓋 AC：AC-RUN-03、AC-UI-07、AC-UI-08、AC-UI-10

前置條件：

- 專案已具備可掃描的 Godot 場景、腳本和資源引用。
- 主 Agent 已補資源引用掃描工具，或提供等價的 `rg`/資源清單掃描步驟。

操作步驟：

1. 掃描 `.tscn`、`.tres`、`.gd`、專案配置和資源清單中的 `res://` 引用。
2. 檢查執行時引用是否只指向允許接入的 `assets/sprites/` 和 `assets/audio/sfx/`。
3. 單獨檢查是否引用 `assets/source/`、`.import` 文件、原始參考大圖作為最終 UI 或 VFX。
4. 檢查核心 UI 是否引用 `assets/sprites/ui/runtime/` 中的執行時 UI 資產，或由這些資產建出的 `.tres`。

通過標準：

- 執行時素材沒有引用 `assets/source/`。
- Godot 程式碼和場景沒有引用 `.import` 文件。
- 核心 UI 不主要依賴預設控制元件、純色框、`draw_rect`、`draw_line`、`draw_circle` 或單色 `StyleBoxFlat` 模擬。
- 升級卡、HUD 主框、結算面板、暫停面板和提示橫幅能追溯到執行時 UI 資產或對應 `.tres`。
- painted 總圖和 reference crop 只作為參考或對照證據，不直接貼成最終 UI。

證據產物：

- 資源引用掃描報告。
- UI runtime 資產引用清單。
- 發現違規引用時的文件路徑和行號。

## TC-RUN-03 模塊邊界與數值集中管理複核

目的：確認核心規則沒有混寫進 UI、動畫或一次性除錯腳本，公共數值有唯一口徑。

覆蓋 AC：AC-RUN-04、AC-RUN-05、AC-RUN-06、AC-PERF-05

前置條件：

- 專案已有實現程式碼。
- 主 Agent 提供程式碼結構說明或模塊清單。

操作步驟：

1. 只讀檢查輸入、戰鬥、刷怪、升級、結算、音效和除錯觀測入口對應模塊。
2. 檢查波次、升級、貓、敵人、音效事件、數量上限等公共數值是否從集中配置或等價唯一口徑讀取。
3. 抽查 UI、動畫和除錯腳本，確認其中沒有承載主要玩法規則。
4. 檢查 v0.1 非目標內容是否沒有進入執行入口和主流程。
5. 檢查除錯加速、截圖、幀序列和狀態快照是否只用於輔助驗證，不能改變正常模式玩法結果。

通過標準：

- 核心系統職責清楚，可追溯到獨立模塊或清晰的腳本邊界。
- 公共數值集中管理，和 `spec/遊戲機制.md` v0.1 數值口徑一致。
- 正常執行入口不包含存檔、賬號、排行榜、商店、揹包、天賦樹、第二張地圖、隨機地圖、多人、後端、複雜 Boss、新增貓種、新增敵人技能、移動端適配或發佈打包優化。
- 除錯參數只改變進入狀態或驗證速度，不改變正常模式口徑。

證據產物：

- 模塊邊界檢查記錄。
- 數值來源清單。
- 非目標內容掃描記錄。

## TC-OBS-01 固定隨機種子可復現

目的：確認同一個種子、同一組輸入和同一套除錯參數下，關鍵狀態推進可復現。

覆蓋 AC：AC-OBS-01

前置條件：

- 主 Agent 補齊固定隨機種子入口。
- 主 Agent 補齊輸入腳本或錄製輸入回放能力。
- 主 Agent 補齊狀態快照導出。

操作步驟：

1. 使用固定 seed A、固定輸入序列和相同除錯參數執行一局到第 2 波中段。
2. 在 0:20、0:45、1:05 導出狀態快照。
3. 使用同樣條件重複執行一次。
4. 對比兩次快照中的關鍵字段。
5. 更換 seed B 執行一次，確認快照允許出現符合隨機邏輯的差異。

通過標準：

- 同 seed、同輸入、同除錯參數下，關鍵狀態一致或在已定義容差內一致。
- 不同 seed 下允許刷怪位置、升級抽取等隨機結果不同。
- 復現能力不依賴人工肉眼判斷。

證據產物：

- 兩組 seed A 快照。
- 一組 seed B 快照。
- 快照對比報告。

## TC-OBS-02 狀態快照字段完整性

目的：確認任意關鍵時刻能導出驗收標準要求的狀態字段。

覆蓋 AC：AC-OBS-02

前置條件：

- 主 Agent 補齊狀態快照導出入口。

操作步驟：

1. 正常模式啟動新一局，導出初始狀態快照。
2. 戰鬥中導出狀態快照。
3. 升級彈窗出現時導出狀態快照。
4. 解鎖黑貓後導出狀態快照。
5. 結算頁導出狀態快照。

通過標準：

- 每份快照至少包含：花子血量、最大血量、當前波次、波次進度、遊戲時間、遊戲狀態、場上敵人數、場上貓彈數、場上奶滴數、擊殺數、當前經驗、升級所需經驗、升級次數、已解鎖武器、各升級層數。
- 字段名稱穩定，數值類型明確。
- 快照能用於自動斷言，不只是一段給人看的文本。

證據產物：

- 多階段狀態快照 JSON。
- 字段完整性檢查報告。

## TC-OBS-03 快速進入關鍵流程

目的：確認升級、勝利、失敗流程不需要每次完整打滿一局才能檢查。

覆蓋 AC：AC-OBS-03

前置條件：

- 主 Agent 補齊快速進入升級、勝利、失敗三個流程的除錯入口。

操作步驟：

1. 使用除錯入口進入即將升級狀態，觸發升級三選一。
2. 使用除錯入口進入即將勝利狀態，推進到勝利結算。
3. 使用除錯入口進入即將失敗狀態，推進到失敗結算。
4. 分別導出狀態快照、截圖和日誌。
5. 檢查這些入口是否隻影響驗證路徑，不改變正常模式規則。

通過標準：

- 三個關鍵流程都能穩定進入。
- 進入後狀態和 UI 與正常流程一致。
- 除錯入口預設關閉，只能通過顯式參數啟用。

證據產物：

- 三類流程的執行日誌。
- 三類流程的狀態快照。
- 升級、勝利、失敗截圖。

## TC-OBS-04 正式視覺證據保留

目的：確認正式驗收有真實執行截圖和動態證據，不只靠日誌。

覆蓋 AC：AC-OBS-04、AC-OBS-05、AC-UI-11

前置條件：

- 主 Agent 補齊真實窗口截圖或幀序列捕獲入口。

操作步驟：

1. 正常模式執行遊戲，保存戰鬥 HUD 截圖。
2. 觸發升級彈窗，保存升級彈窗截圖。

證據產物：

- 除錯輔助層截圖記錄，若本輪使用。

## TC-INPUT-01 移動、鏡頭和地圖邊界

目的：確認玩家輸入、移動速度方向一致性、鏡頭跟隨和地圖邊界可用。

覆蓋 AC：AC-INPUT-01、AC-INPUT-02、AC-MAP-01、AC-MAP-02、AC-MAP-03、AC-MAP-05、AC-MAP-06

前置條件：

- 主 Agent 補齊輸入腳本或人工操作記錄模板。
- 主 Agent 補齊位置和速度快照字段。

操作步驟：

1. 在正常模式下分別按 W、A、S、D 和方向鍵移動。
2. 分別按斜向組合鍵移動，例如 W+D、W+A、S+D、S+A。
3. 導出單軸和斜向移動速度快照。
4. 移動到地圖四周邊界，觀察是否能走出地圖視覺邊界或進入不可讀區域。
5. 截取不同地圖位置的正常畫面。
6. 檢查鏡頭只顯示地圖一部分，Camera2D zoom 位於 0.8 到 1.2。

通過標準：

- WASD 和方向鍵都能穩定移動花子。
- 上下左右和斜向移動穩定，斜向移動不能明顯快於單軸移動。
- 鏡頭跟隨花子移動。
- 玩家不能走出地圖視覺邊界或進入不可讀地圖外區域。
- 遊戲使用一張固定戶外大地圖，不做地圖切換、隨機地圖、迷宮、鑰匙門或複雜探索。
- 地圖明顯大於屏幕，一屏約看到 `full_outdoor_map_painted_4096x2305.png` 整圖四分之一。
- 地圖邊界通過圍欄、樹牆、石牆、水面或其他視覺方式表達清楚。
- 玩家出生點和刷怪區附近可讀，不過度擁擠。

證據產物：

- 輸入記錄。
- 移動速度快照。
- 地圖邊界截圖。
- Camera2D zoom 和視口記錄。

## TC-INPUT-02 自動攻擊與升級選擇交互

目的：確認玩家不需要手動瞄準，升級三選一可點擊且選擇後恢復戰鬥。

覆蓋 AC：AC-INPUT-03、AC-INPUT-04、AC-INPUT-07、AC-GROWTH-05

前置條件：

- 主 Agent 補齊快速進入升級流程入口。
- 場上可生成敵人。

操作步驟：

1. 正常模式下只移動花子，不點擊攻擊鍵、不操作滑鼠瞄準。
2. 觀察貓是否從花子附近自動發射並攻擊敵人。
3. 使用快速入口觸發升級三選一。
4. 分別點擊三個升級卡位置，至少覆蓋三次執行。
5. 選中升級後導出快照，並繼續觀察戰鬥。

通過標準：

- 玩家無需手動瞄準或主動攻擊。
- 貓會自動從花子附近發射並攻擊敵人。
- 升級三選一每次出現 3 個升級項，除非可選項不足 3 個。
- 玩家能用滑鼠點擊任意可選升級項。
- 選中後升級立即生效，升級 UI 關閉，戰鬥恢復。
- 升級彈窗期間戰鬥暫停，升級 UI 仍可點擊。

證據產物：

- 自動攻擊幀序列。
- 升級點擊前後狀態快照。
- 三個卡片點擊記錄。

## TC-INPUT-03 暫停與恢復

目的：確認 Esc 或 P 暫停恢復可用，暫停時戰鬥實體停止但 UI 可操作。

覆蓋 AC：AC-INPUT-06

前置條件：

- 戰鬥中至少存在敵人、貓彈、經驗或奶滴中的任意兩類動態對象。
- 狀態快照包含遊戲時間和對象位置。

操作步驟：

1. 正常戰鬥中按 Esc 暫停。
2. 暫停後等待真實時間 3 秒，連續導出狀態快照。
3. 檢查戰鬥計時、刷怪、敵人、彈體和經驗移動是否停止。
4. 使用 UI 或再次按 Esc 恢復。
5. 用 P 重複一次暫停和恢復。

通過標準：

- Esc 和 P 都能暫停和恢復遊戲。
- 暫停期間戰鬥計時不推進。
- 刷怪、敵人、貓彈、奶滴和經驗移動停止。
- 暫停 UI 或恢復操作仍可用。
- 恢復後戰鬥繼續推進。

證據產物：

- 暫停前、中、後狀態快照。
- 暫停界面截圖。

## TC-COMBAT-01 三種貓機制差異

目的：確認三種貓的機制和表現都不同，且各自按事實源數值執行。

2. 在花子周圍佈置多個不同距離敵人，觀察橘貓是否朝發射時最近敵人直線撲擊。

- 橘貓開局即擁有。
- 橘貓朝當時距離最近的敵人直線撲擊，不是隨機方向。

- 每隻貓彈都有明確傷害、飛行速度、飛行時間、命中邏輯和同屏上限，達到上限後不能無限新增。
- 複核者能用自己的話說出三種貓的大致差異。

證據產物：

- 三種貓的狀態快照。
- 三種貓命中和飛行幀序列。
- 同屏上限檢查記錄。
- 人工視覺複核記錄。

## 待主 Agent 補齊的驗證工具

以下不是未覆蓋 AC，而是執行本文件前需要補齊的工具或入口：

- Godot headless smoke：加載 `scenes/Main.tscn`、執行指定秒數、輸出日誌。
- 固定 seed 和輸入回放：支持同 seed、同輸入、同除錯參數復現。
- 狀態快照導出：按 AC-OBS-02 字段導出結構化快照。
- 快速流程入口：升級、勝利、失敗、指定波次、第 5 波壓力、指定敵人和指定升級層數。
- 真實窗口截圖和幀序列：保存正常戰鬥、升級彈窗、結算頁、動態戰鬥證據。
- HUD 幾何測量：能測血條、經驗條槽體和填充區域的像素位置。
- 資源引用掃描：識別執行時素材引用、UI runtime 資產、禁止路徑和預設控制元件替代風險。
- 音效事件日誌：記錄關鍵音效事件、資源路徑和加載結果。
- 性能觀測：記錄內存、節點數量、對象池計數、活躍對象數量、日誌錯誤和幀時間。
