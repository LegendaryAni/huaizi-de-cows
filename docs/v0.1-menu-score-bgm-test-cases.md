## 測試入口規劃

本輪要求實現方補齊下面的除錯入口和報告字段。本文件只提出測試要求，不實現這些入口；這些入口、截圖和 `validation_report` 字段未落地前，對應測試不算通過。

| 入口 | 用途 | 必需證據 |
| --- | --- | --- |
| `--debug-mode=menu_probe` | 啟動到開始界面，自動枚舉按鈕、打開開發團隊頁和成績頁。 | `validation_report.menu_probe`、`capture_dir/menu_start_normal.png`、`capture_dir/menu_developers_normal.png`、`capture_dir/menu_scores_empty_normal.png` |
| `--debug-mode=scores_probe` | 清理本地成績、注入可控成績樣本、驗證前 10 名、排序、空成績佔位和重啟後仍保留。 | `validation_report.scores_probe`、`capture_dir/menu_scores_empty_normal.png`、`capture_dir/menu_scores_top10_normal.png`、重啟後讀取證據 |
| `--debug-mode=failure_score_probe` | 快速進入失敗結算，驗證分數、破紀錄、退出進程請求和重玩。 | `validation_report.failure_score_probe`、`capture_dir/result_failure_score_normal.png` |
| `--debug-mode=bgm_probe` | 驗證 BGM 文件來源、`assets/audio/sfx/` 執行時路徑、加載、播放、替換結果和音訊文件記錄。 | `validation_report.bgm_probe`、音訊加載日誌或事件字段 |

通用執行命令模板：

```bash
godot --headless --path . -- --debug-mode=<probe> --validation-report=<report.json> --run-seconds=<seconds> --time-scale=6
```

需要截圖的用例使用真實窗口或可保存 viewport 的執行方式：

```bash
godot --path . -- --debug-mode=<probe> --validation-report=<report.json> --capture-dir=<capture_dir> --run-seconds=<seconds> --time-scale=6
```

## MSB-TC-01 開始界面入口與開發者署名

目的：確認遊戲啟動先出現開始界面，開始界面提供“開始遊戲”“成績”“開發團隊”，點擊“開發團隊”後顯示 aya 和 HexBlank，且一行一個名字。

覆蓋需求：R-MSB-01

覆蓋 AC：AC-LOOP-01、AC-INPUT-05、AC-UI-03、AC-UI-05、AC-OBS-04

前置條件：

- 實現方補齊 `--debug-mode=menu_probe`。
- `menu_probe` 能導出開始界面、開發團隊頁、成績頁的 UI 狀態快照和截圖，並記錄開發者姓名展示方式。

操作步驟：

1. 使用 `--debug-mode=menu_probe --validation-report=... --capture-dir=...` 啟動主場景。
2. 在未點擊任何按鈕時保存開始界面截圖 `menu_start_normal.png`。
3. 在報告中記錄開始界面可點擊項文本、可見性、可用狀態和當前遊戲狀態。
4. 自動點擊或調用“開發團隊”入口，保存 `menu_developers_normal.png`。
5. 返回開始界面後自動點擊或調用“成績”，保存成績頁截圖。

自動斷言：

- `validation_report.game_state` 或 `validation_report.menu_probe.current_screen` 表示當前處於開始界面，不直接進入戰鬥。
- `validation_report.menu_probe.start.buttons` 精確包含中文文本“開始遊戲”“成績”“開發團隊”。
- 三個入口均 `visible == true` 且 `enabled == true`。
- `validation_report.menu_probe.developers.names` 精確包含 `aya` 和 `HexBlank`，且不缺字、不改大小寫。
- `validation_report.menu_probe.developers.display_mode == "developer_team_screen"`。
- `validation_report.menu_probe.developers.names_layout == "one_per_line"`。
- `validation_report.menu_probe.start.unexpected_completion_texts` 為空；畫面不出現“已完成需求”等驗收說明文字。

視覺複核：

- `menu_start_normal.png` 和 `menu_developers_normal.png` 中按鈕、標題、姓名不重疊、不裁切，標題和姓名均位於面板內容區內。
- UI 文案為中文；開發者姓名按事實源保留英文大小寫。
- 正常截圖中無除錯輔助層痕跡。

## MSB-TC-02 “開始遊戲”進入戰鬥閉環

目的：確認點擊“開始遊戲”後進入正常一局，不破壞 v0.1 從開始到戰鬥、結算、重玩的閉環。

覆蓋需求：R-MSB-01

覆蓋 AC：AC-LOOP-01、AC-INPUT-05、AC-RUN-02、AC-OBS-02

前置條件：

- 實現方補齊 `--debug-mode=menu_probe` 的開始按鈕自動操作。
- 狀態快照保留 `game_state`、`game_time`、`current_wave`、`player_hp`、`unlocked_weapons` 等既有字段。

操作步驟：

1. 使用 `menu_probe` 啟動開始界面。
2. 自動觸發“開始遊戲”。
3. 執行 5 秒遊戲時間。
4. 導出 `after_start_game` 狀態快照。

自動斷言：

- 點擊前狀態為開始界面；點擊後狀態為 `combat` 或等價戰鬥狀態。
- `after_start_game.game_time > 0`。
- `after_start_game.current_wave == 1`。
- `after_start_game.player_hp == 100`。
- `after_start_game.unlocked_weapons` 僅包含開局武器橘貓。
- 日誌中沒有腳本解析錯誤、資源加載錯誤或執行時致命錯誤。

## MSB-TC-03 成績頁空狀態與最高 10 個分數

目的：確認成績頁在沒有成績時顯示“？？?”；有成績時只顯示最高 10 個分數，並按分數高低穩定排序。

覆蓋需求：R-MSB-03

覆蓋 AC：AC-UI-03、AC-UI-05、AC-OBS-02、AC-OBS-04、AC-RUN-06

前置條件：

- 實現方補齊 `--debug-mode=scores_probe`。
- `scores_probe` 支持清理本地成績、注入至少 12 條可控成績樣本、寫入本地持久化成績、重啟 Godot 後再次讀取成績。
- `validation_report.scores_probe` 必須包含 `persistence_path`、`cleanup_method`、`cleanup_result`、`written_scores`、`restart_evidence`、`loaded_scores_after_restart`、`uses_account_or_backend`。
- `restart_evidence` 必須能證明寫入和讀取發生在兩次獨立啟動中，例如包含兩次執行的 `run_id`、進程號、啟動時間或等價可區分字段。

操作步驟：

1. 以空成績狀態執行 `scores_probe`，打開成績頁並保存 `menu_scores_empty_normal.png`。
2. 讀取 `validation_report.scores_probe.empty_state`。
3. 注入 12 條亂序成績，例如 `100, 900, 300, 700, 1100, 500, 200, 800, 400, 1000, 600, 1200`。
4. 打開成績頁並保存 `menu_scores_top10_normal.png`。
5. 讀取 `validation_report.scores_probe.displayed_scores`。
6. 結束當前 Godot 進程後重新啟動專案，使用同一個本地持久化路徑讀取成績。
7. 導出 `validation_report.scores_probe.loaded_scores_after_restart` 和 `restart_evidence`。

自動斷言：

- 空成績時 `empty_placeholder == "？？?"`，且 `displayed_scores` 為空。
- 有成績時 `displayed_scores.size() == 10`。
- `displayed_scores` 精確等於注入成績中的前 10 個最高分，按降序排列：`[1200, 1100, 1000, 900, 800, 700, 600, 500, 400, 300]`。
- 不顯示第 11、12 名分數 `200`、`100`。
- `validation_report.scores_probe.uses_account_or_backend == false`；不得把本地成績頁實現成賬號、後端或在線排行榜功能。
- `persistence_path` 非空，指向本地專案或 Godot 用戶資料路徑，不是網絡地址。
- `cleanup_method` 非空，且 `cleanup_result.success == true`。
- `written_scores` 包含本次注入的 12 條成績。
- `restart_evidence.first_run_id != restart_evidence.second_run_id`，或提供等價證據證明發生過獨立重啟。
- `loaded_scores_after_restart` 至少包含寫入後的最高 10 個分數，且前 10 名與 `displayed_scores` 一致。
- `uses_account_or_backend == false`；報告中不得出現賬號登錄、遠端 API、在線排行榜、服務端地址或網絡同步字段。

視覺複核：

- 空成績截圖中能清楚看到“？？?”。
- 前 10 名分數在 `menu_scores_top10_normal.png` 中不重疊、不裁切。
- 成績頁不出現驗收說明文字或除錯輔助層。

通過限制：

- `scores_probe`、持久化字段、清理字段、重啟讀取證據任一缺失時，R-MSB-03 不算通過。

## MSB-TC-04 失敗結算分數、破紀錄、退出與重玩

目的：確認花子死亡後進入失敗結算，顯示本局分數和是否破記錄，並提供“退出”“重玩”兩個選項；“退出”只能觸發退出進程請求。

覆蓋需求：R-MSB-02

覆蓋 AC：AC-LOOP-02、AC-LOOP-05、AC-LOOP-06、AC-INPUT-05、AC-UI-03、AC-UI-05、AC-OBS-03、AC-OBS-04

前置條件：

- 實現方補齊 `--debug-mode=failure_score_probe`。
- `failure_score_probe` 能注入或構造兩次失敗：一次非破紀錄，一次破紀錄。
- 報告字段包含失敗前分數、歷史最高分、是否破紀錄、按鈕文本、重玩後初始狀態、退出進程請求結果。

操作步驟：

1. 使用 `failure_score_probe` 快速進入死亡失敗流程。
2. 保存失敗結算截圖 `result_failure_score_normal.png`。
3. 導出 `validation_report.failure_score_probe.first_failure`。
4. 觸發“重玩”，導出 `after_replay` 狀態快照。
5. 再構造更高分失敗，導出 `record_failure`。
6. 觸發“退出”，記錄退出進程請求。自動探針允許攔截真實 `quit` 以便寫出報告，但必須記錄攔截到的退出請求。

自動斷言：

- 死亡後 `game_state == "failure"` 或等價失敗狀態。
- 失敗結算按鈕文本精確包含“退出”和“重玩”。
- 失敗結算展示的分數字段為數值型，且與報告中的 `score` 一致。
- 非破紀錄樣本 `is_new_record == false`；破紀錄樣本 `is_new_record == true`。
- “重玩”後 `player_hp == 100`、`current_wave == 1`、`game_time == 0`、`kills == 0`、`upgrade_count == 0`、`unlocked_weapons` 回到開局狀態。
- “退出”觸發明確事件 `exit_requested == true`。
- 如果自動探針攔截真實退出，必須記錄 `quit_intercepted == true` 和被攔截的退出請求來源。
- `returned_to_start_menu_after_exit == true` 不能作為通過證據；如果點擊“退出”只是返回開始界面且沒有退出進程請求，本用例不通過。

視覺複核：

- `result_failure_score_normal.png` 中能看見失敗標題、分數、破紀錄狀態、“退出”“重玩”。
- 分數、破紀錄文案、按鈕和既有結算統計不互相遮擋、不裁切。
- 結算面板仍滿足居中彈出和中文 UI 要求。

通過限制：

- `failure_score_probe`、失敗截圖、分數字段、破紀錄字段、退出進程請求字段任一缺失時，R-MSB-02 不算通過。
- 本輪測試不自行規定分數公式，只要求分數為一致的數值型結果，並通過受控樣本驗證記錄比較。

## MSB-TC-05 BGM 提取、替換與執行時加載

目的：確認背景音樂來自指定 MP4 提取音訊，執行時加載成功並作為背景音樂播放，不繼續使用舊背景音樂或空音訊。

覆蓋需求：R-MSB-04

覆蓋 AC：AC-RUN-02、AC-RUN-03、AC-FEEDBACK-06、AC-OBS-02

前置條件：

- 實現方補齊 `--debug-mode=bgm_probe`。
- 實現方從 `/Users/wawa/Downloads/39995331_da2-1-16.mp4` 提取音訊並接入 Godot 執行時資源。
- BGM 執行時路徑固定為 `res://assets/audio/sfx/background_bgm_01.ogg`，或同目錄 `res://assets/audio/sfx/` 下的專案內音訊文件。
- 實現方必須更新 `assets/audio/README.md`，記錄指定 MP4 來源和執行時文件映射；`assets/audio/LICENSES.md` 不要求記錄用戶提供的 BGM 映射。本測試只驗證記錄存在，不修改素材文件。

操作步驟：

1. 執行 `bgm_probe`，導出 `validation_report.bgm_probe`。
2. 掃描執行時音訊路徑、加載日誌和 `assets/audio/README.md`。
3. 啟動戰鬥狀態至少 5 秒，記錄 BGM 播放狀態。
4. 如支持音訊事件日誌，記錄 `bgm_started`、`bgm_loop_enabled` 或等價字段。

自動斷言：

- `bgm_probe.source_input_path == "/Users/wawa/Downloads/39995331_da2-1-16.mp4"`。
- `bgm_probe.runtime_path == "res://assets/audio/sfx/background_bgm_01.ogg"`，或 `bgm_probe.runtime_path` 指向 `res://assets/audio/sfx/` 下的專案內音訊文件。
- `bgm_probe.runtime_path` 不能直接引用 `/Users/wawa/Downloads/39995331_da2-1-16.mp4`，也不能指向 `assets/source/`、專案外路徑或非 `assets/audio/sfx/` 目錄。
- `bgm_probe.stream_loaded == true`。
- `bgm_probe.stream_length_seconds > 0`。
- `bgm_probe.playing_in_combat == true`。
- `bgm_probe.is_silent_placeholder == false`。
- `bgm_probe.replaced_previous_bgm == true`，或報告中能證明當前唯一 BGM 為本輪提取音訊。
- `bgm_probe.audio_readme_contains_source_record == true`，且 `assets/audio/README.md` 中可找到 `39995331_da2-1-16.mp4` 和執行時 BGM 文件名。
- `bgm_probe.audio_licenses_omits_user_bgm_mapping == true`，即 `assets/audio/LICENSES.md` 不記錄用戶提供的 BGM 映射。
- `sfx_missing` 為空，且新增 BGM 不破壞既有 SFX 加載。
- 執行日誌沒有資源加載錯誤、解碼錯誤或執行時致命錯誤。

人工或工具複核：

- 音訊授權和來源記錄已更新到音訊文件，且能追溯到指定 MP4。
- 執行時資源路徑位於 `assets/audio/sfx/`，符合 AC-RUN-03 的執行時音訊目錄口徑。

通過限制：

- `bgm_probe`、執行時路徑斷言、音訊加載斷言、`assets/audio/README.md` 記錄任一缺失時，R-MSB-04 不算通過。

## 覆蓋限制

- `menu_probe`、`scores_probe`、`failure_score_probe`、`bgm_probe` 是本輪必須落地的測試入口；入口未實現、報告字段缺失或截圖缺失時，對應需求不算通過。
- 成績持久化、退出進程請求、BGM `assets/audio/sfx/` 路徑和音訊文件記錄均已有明確通過口徑。
- 本輪測試不自行規定分數公式，但必須驗證分數存在、一致、可用於破紀錄比較。
